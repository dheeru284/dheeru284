# API Design

REST + JSON over HTTPS. Base path `/api/v1`. The OpenAPI schema is generated by
FastAPI at `/api/v1/openapi.json`, with interactive docs at `/api/v1/docs`.

**Phase 0 implements only the System endpoints (§3.1).** All others are the
Milestone 1 contract, marked with the phase that delivers them.

## 1. Conventions

- **Auth:** `Authorization: Bearer <JWT>` (Phase 1a). Roles: see PRODUCT_REQUIREMENTS §3.
- **IDs:** UUID strings.
- **Timestamps:** ISO 8601, UTC, with a `Z` suffix.
- **Enums:** upper-snake strings matching `app/domain/enums.py`.
- **Pagination:** cursor-based. `?limit=50&cursor=<opaque>` → `{"items": [...], "next_cursor": "..."|null}`. Max `limit` 200.
- **Idempotency:** `POST /submissions` accepts `Idempotency-Key`. A repeated key from the same user returns the original resource with `200` instead of `201`.
- **Errors:** RFC 9457 `application/problem+json`:
  ```json
  {"type": "https://bnip.local/problems/invalid-transition",
   "title": "Invalid state transition", "status": 409,
   "detail": "Claim is APPROVED; cannot move to ASSESSING", "instance": "/api/v1/claims/…"}
  ```
  Validation errors (422) add `errors: [{loc, msg, type}]`.
- **Provenance in responses:** any object produced by an AI carries
  `ai_run: {id, agent_name, provider, model, prompt_id, prompt_version}`, so
  clients can always show where it came from (including the MOCK badge).

## 2. Status codes

`200` OK · `201` created · `202` accepted (async work enqueued) · `400` bad request ·
`401` unauthenticated · `403` forbidden (role or four-eyes rule) · `404` · `409`
conflict or invalid state transition · `422` validation · `429` rate limited ·
`503` dependency unavailable (readiness only).

## 3. Endpoints

### 3.1 System (Phase 0, implemented)
| Method | Path | Auth | Description |
|---|---|---|---|
| GET | `/health` | none | Liveness: `{"status":"ok","version":"…"}` |
| GET | `/health/ready` | none | Readiness: checks database, pgvector extension, Redis, configured LLM and embedding providers. `200` if all required checks pass, else `503`. Body: `{"status":"ok"|"degraded", "checks":{name:{ok, required, detail}}}` |
| GET | `/system/providers` | none (Phase 0) → ADMIN (Phase 1a) | Configured providers: `{"llm":{name, model, is_mock}, "embedding":{name, model, dimensions, is_mock}}` |

Readiness treats the LLM provider as *required* only when `BNIP_ENV=production`.
In development, an unreachable Ollama reports `degraded` with `200`, so the API
stays usable for non-AI work.

### 3.2 Auth (Phase 1a)
| Method | Path | Role | Description |
|---|---|---|---|
| POST | `/auth/token` | — | `{email, password}` → `{access_token, token_type, expires_in}` |
| GET | `/auth/me` | any | current user |
| POST | `/users` | ADMIN | create a user |
| PATCH | `/users/{id}` | ADMIN | change role / active (audited) |

### 3.3 Submissions and claims (Phase 1a)
| Method | Path | Role | Description |
|---|---|---|---|
| POST | `/submissions` | SUBMITTER+ | Create; enqueues extraction. `201` `{submission, pipeline_job_id}` |
| GET | `/submissions` | SUBMITTER+ | Own submissions (ANALYST+: all) |
| GET | `/submissions/{id}` | owner / ANALYST+ | Submission with its claims |
| GET | `/claims` | ANALYST+ | Filter: `status`, `claim_type`, `verdict`, `created_after` |
| GET | `/claims/{id}` | owner / ANALYST+ | Claim, current status, latest assessment summary, pipeline jobs |
| POST | `/claims` | ANALYST+ | Add a human-authored claim to a submission |
| PATCH | `/claims/{id}` | ANALYST+ | Edit text, type, checkworthy (only before ASSESSING; audited) |
| POST | `/claims/{id}/pipeline` | ANALYST+ | `{"from_stage": "RETRIEVAL"}`: restart from a stage. `202` |
| GET | `/claims/{id}/pipeline` | ANALYST+ | Stage graph data: jobs, statuses, timings (feeds React Flow) |

`POST /submissions` request:
```json
{"raw_text": "…", "source_url": "https://…", "language": "en",
 "statement_date": "2026-10-01", "speaker_entity_id": "…", "context_note": "…"}
```

### 3.4 Entities, publishers, sources (Phase 1b)
| Method | Path | Role | Description |
|---|---|---|---|
| GET/POST | `/entities` | ANALYST+ | List / create public speakers and organizations |
| GET | `/publishers` | ANALYST+ | List with tiers |
| POST | `/publishers` | ANALYST+ | Create (tier `UNRATED`) |
| PATCH | `/publishers/{id}/tier` | ADMIN | `{reliability_tier, tier_rationale}` (rationale required; audited) |
| POST | `/sources` | ANALYST+ | Ingest `{title, url, publisher_id, source_type, published_at, language, content_text}`. Hashes, chunks, enqueues embedding. A duplicate hash returns `200` with the existing source. |
| GET | `/sources` | ANALYST+ | List/search |
| GET | `/sources/{id}` | ANALYST+ | Metadata and the full snapshot |
| GET | `/sources/{id}/chunks` | ANALYST+ | Chunks with offsets |

### 3.5 Evidence and assessments (Phase 1b–1c)
| Method | Path | Role | Description |
|---|---|---|---|
| GET | `/claims/{id}/retrievals` | ANALYST+ | Raw retrieval results |
| GET | `/claims/{id}/evidence` | owner / ANALYST+ | Evidence with source summary and latest ranking |
| POST | `/claims/{id}/evidence` | ANALYST+ | Human evidence `{source_id, quote, stance, stance_rationale}`; server finds the offsets and rejects the quote with `422` if it isn't present in the source |
| GET | `/claims/{id}/assessments` | owner / ANALYST+ | All revisions |
| GET | `/assessments/{id}` | owner / ANALYST+ | Verdict, rationale, citations (expanded), critiques, ai_run |
| GET | `/assessments/{id}/critiques` | ANALYST+ | |

Owners (SUBMITTER) see evidence and assessments only after the claim is `APPROVED`.

### 3.6 Review (Phase 1d)
| Method | Path | Role | Description |
|---|---|---|---|
| GET | `/review-tasks` | REVIEWER+ | Queue; filter `status`, `reason`; sorted by priority, then age |
| GET | `/review-tasks/{id}` | REVIEWER+ | Task plus full review packet (claim, evidence, assessment, critiques, provenance) |
| POST | `/review-tasks/{id}/claim` | REVIEWER+ | Assign to self (`409` if already claimed) |
| POST | `/review-tasks/{id}/release` | assignee | Unassign |
| POST | `/review-tasks/{id}/decision` | assignee | `{decision, final_verdict?, notes?}`. `403` if the reviewer made the submission. |

### 3.7 Provenance and audit (Phase 1a+)
| Method | Path | Role | Description |
|---|---|---|---|
| GET | `/ai-runs/{id}` | ANALYST+ | Full run: messages, parameters, output, hashes |
| GET | `/audit-events` | ADMIN (own entity's events: ANALYST+) | Filter `entity_type`, `entity_id`, `actor_id`, `action`, time range |
| GET | `/audit-events/verify` | ADMIN | Recompute the hash chain: `{ok, checked, first_broken_seq|null}` |

## 4. Async work

Endpoints that start pipeline work return `202` with `pipeline_job_id`.
Clients poll `GET /claims/{id}/pipeline`. Server-sent events are a Phase 2
option; polling stays supported.

## 5. Versioning

Breaking changes need `/api/v2`. Additive changes (new fields, endpoints, enum
values) are allowed in v1. Clients must tolerate unknown fields and enum values.
